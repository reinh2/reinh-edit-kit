# Reinh Edit Kit - с чего начать

Человек пишет задачу своими словами. Ваша работа - понять, какие этапы нужны, и пройти их нужными скиллами по порядку, не спрашивая лишнего.

## Перед работой - прочитать
- `YOUR_RULES.md` - правила владельца этого проекта (стиль, что можно и нельзя). Они главнее общих умолчаний.
- `kit.config.json` - язык, модель Whisper, микрофоны, цвета, шрифт, контакты, форматы.
- `docs/EDIT_STANDARD.md` - стандарт монтажа; `docs/DELIVERY_PROFILES.md` - форматы выдачи; `docs/LIMITS.md` - чего система не умеет.

## Карта скиллов
| Этап | Скилл | Результат |
|---|---|---|
| Черновой монтаж | `kit-rough-cut` | лучшие дубли, паузы в измеренной тишине, EDL |
| Монтаж под ключ | `kit-video-edit` | всё по цепочке + сборка в Remotion |
| Звук | `kit-audio-post` | голос по пресету микрофона, музыка, SFX, мастер -15 LUFS |
| Субтитры | `kit-captions` | пословные субтитры, отдельный .srt |
| Проверка | `kit-qc` | технический + редакторский QC, отчёт |
| Анимации Remotion | официальные `remotion-*` | `npx skills add remotion-dev/skills` |
| Резка по тишине, экспорт в редакторы | официальные `auto-editor*` | `npx skills add WyattBlue/auto-editor` |

## Типовые цепочки
- «Вот дубли, смонтируй» → `kit-video-edit` (внутри: rough-cut → вставки → captions → audio-post → qc).
- «Убери паузы / выбери дубли» → `kit-rough-cut`.
- «Почисти звук / новый микрофон» → `kit-audio-post` (новый микрофон - сначала калибровка: `voice_master.py analyze`).
- «Перемонтируй, монтаж плохой» → аудит по `docs/EDIT_STANDARD.md` + `scripts/qc/editorial_qc.py` → новый EDL → сборка → `kit-qc`.
- «Проверь перед публикацией» → `kit-qc`.

## Правила
1. **Сначала черновик, потом замечания человека, потом финал.** Любой монтаж - сначала быстрый черновик (720p, `--scale`), человек смотрит и пишет замечания с таймкодами, вы исправляете все, и только потом один рендер в полном качестве. Никогда не говорите «готово» без просмотра человеком: вкус, эмоцию дубля и финальное ухо система не заменяет (`docs/LIMITS.md`).
2. Начните с одной строки плана: какие скиллы и в каком порядке. Если задача однозначна - сразу делайте.
3. Спрашивайте только то, без чего нельзя (нет исходников, непонятно, какой формат). Остальное - умолчания из `kit.config.json` и `docs/`.
4. **Исходники неприкосновенны.** Только чтение; промежуточное - в `work/`, готовое - в `exports/`. В FFmpeg исходник - одним явным путём в кавычках сразу после `-i`, никогда через шаблон `*` и никогда в команде с `-y`, где путь может попасть на место выхода (так однажды агент перезаписал десять исходников).
5. Ничего не загружать во внешние сервисы и ничего не публиковать без явного разрешения человека. Расшифровка - локально (whisper.cpp).
6. В конце - что готово, где файлы, что не проверено, и одна следующая рекомендация.
